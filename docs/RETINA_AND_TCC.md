# Retina 坐标与 TCC 权限：两个「不报错但就是不动」的坑

2026年11月3日 · macOS 实测记录。

## 一、Retina 坐标差一倍

### 现象

桌面 Agent 截图给模型看，模型说「点在 (886, 402)」，程序照做，**点到了完全不相干的地方**。
不报错、不抛异常，表现就是「点了没反应」。

### 实测数值

| | 数值 |
|---|---|
| `screencapture` 截图 | **3456 × 2234**（物理像素） |
| Finder 桌面 bounds（点击可用） | **1728 × 1117**（逻辑坐标） |
| 比值 | **2.0** |

`screencapture` 给的是**物理像素**，`System Events` 的 `click at` 要的是**逻辑坐标**。

### 对照实验（决定性）

目标窗口逻辑位置 `243,141`，尺寸 `603×505`（即 x 范围 243–846）。

| 做法 | 实际点击坐标 | 命中 |
|---|---|---|
| 物理坐标直点 | (886, 402) | ❌ 点到**另一个窗口**（886 已超出目标窗口右边界 846） |
| 传 `coords: physical` | 自动 ÷2 → (443, 201) | ✅ 命中**目标窗口** |

### 做法

1. **查比值**，不要假设是 2.0：

```python
phys_w = 读 PNG 头里的宽（screencapture 产物）
logical_w = AppleScript 读 Finder 的 desktop bounds 宽
scale = phys_w / logical_w
```

2. **在返回值里带上语义**，不要只给数字：

```jsonc
{"size": "3456x2234", "scale": 2.0, "logicalSize": [1728, 1117],
 "coordsAre": "physical", "clickHint": "ui_click 传 coords='physical' 会自动换算"}
```

3. **点击接口显式声明坐标系**，默认用原生语义（逻辑坐标），物理坐标必须显式声明。

**踩坑点**：把「自动换算」做成默认行为是危险的——调用方给的到底是哪一种，
接口自己猜不出来。宁可多一个参数，也不要默默乘 2 或除 2。

## 二、TCC 权限静默失效

### 现象

系统设置里明明勾了辅助功能，代码还是点不动；**不弹窗、不报错**。

### 原因

macOS 的 TCC（Transparency, Consent, and Control）按**二进制签名**记账。
程序一重编译、签名一变，系统就把它当成**另一个应用**，权限不再适用，
并且在后台静默拒绝。

### 做法

1. **自检前置**：动手前先跑一次环境自检，把「权限没了」和「代码写错」分开。
   一次检查完：辅助功能、屏幕录制、Retina 缩放、依赖工具、本机服务。
2. **调试期授权对象选对**：授权给**运行代码的那个宿主**（终端 / IDE / 解释器），
   而不是每次重编译都变的产物。
3. **改完要重启服务**：TCC 按进程记账，权限变更后旧进程仍按旧账走。
4. **报错要带处理指引**：`-1719` / `-25211` 这类码对用户没有意义，
   必须转成「去哪个设置页做什么」+「改完要重启」。

## 三、附带：中文输入法

逐字 `keystroke` 长文本有两个独立的坑：

1. **丢字符**：实测 `dogpaw` 打出来是 `Dog-as`。长文本必须走剪贴板。
2. **被输入法吞掉**：中文输入法激活时，英文字符被当成拼音，弹出候选框而不是出字。

所以：**长文本默认走剪贴板粘贴，与输入法无关**；「模拟真人逐字打字」只用于明确需要它的场景，
并且必须接受可能丢字。

查当前输入法（实测 AppleScript 的 `name of current keyboard layout` 在本机取不到）：

```bash
defaults read com.apple.HIToolbox AppleCurrentKeyboardLayoutInputSourceID
# → com.apple.keylayout.ABC
```

切输入法的快捷键各版本不同，**只能尝试并如实报告结果，不能假装切过去了**。
