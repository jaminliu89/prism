# Prism × 取流通道分层：媒体捕获的层梯

## 定位与上位路由

集团 REA / 逆向主线负责协议与算法还原；Prism 只维护**「证据在哪一层取、取到什么程度算证据」**这份判据，不实现下载器、不内置嗅探扩展、不替任何产品做取流。本文件不含任何站点的私有参数（签名盐、CDN 口令、密钥），只收在多个产品上重复验证过的结构性经验。

来源：狗刨下载器（浏览器扩展，B站 / 抖音 / YouTube / 通用站点）2026-11 的两轮通道重构。私有实现留在产品主库，这里只回收可迁移的判据。

## 一、最贵的一类错误：同名不同层

同一句「fetch 这条地址会失败」，在不同执行上下文里含义完全不同：

| 谁在 fetch | 受不受 CORS | 结果 |
|---|---|---|
| 页面上下文（content script） | 受 | 对方不给 `Access-Control-Allow-Origin` 就必然失败 |
| **扩展上下文（offscreen / 扩展页面）** | **不受**（有 host permission） | 正常拿到字节 |
| `chrome.downloads` | 不适用（**不经过 declarativeNetRequest**） | 站点校验 Referer 时必然 403 |

误判的代价是**三连**：结论错（「这个站只能边播边存」）→ 代码错（硬编码强制降级）→ 文档错（写进 AGENTS 当事实）。后来实测推翻：同一条轨道在扩展上下文里 `Range: 206`，14 秒下完 73 MB。

**判据**：写下「X 不可行」之前，必须先写清「在哪个上下文、用什么 API、失败返回什么」。三个要素缺一个，这条结论就不许进文档。

## 二、层梯：按「字节在哪一层」拆，而不是按工具拆

| 层 | 拿到什么 | 绕过了什么 | 代价 | 典型判据 |
|---|---|---|---|---|
| 元数据 / SSR | 直链字符串 | 签名、风控 | 最便宜，也最爱失效 | 带失效日期的窗口期记录 |
| 网络层 | 原始 HTTP 响应体 | 播放依赖、MSE | 调试黄条 / 缓存淘汰 | 必须能说出「抓到了几条」 |
| 页面 JS 层 | 签名、解密后明文 | 签名、SW | hook 时机 / CSP | 借力而非破解 |
| 播放管线层 | appendBuffer 后的帧 | 一切网络校验 | 需要人播一遍 | init segment 是否完整 |
| 加密层 | 解密后的媒体 | AES / CENC | key 获取是法律问题 | 逐字节比对 |
| 客户端层 | App 内明文流量 | SSL pinning | 已超出浏览器产品范围 | — |
| 物理 / 录屏层 | 像素与音频 | **一切**（含 DRM） | 实时 + 有损 | 「通杀」不等于「可用」 |

**判据**：新增能力时先问「它属于哪一层」，不要因为「这次能跑」就把两层混在一个按钮里。同一层的多个方法做成**可切换通道 + 自动降级链**，而不是互相替换。

## 三、五条纪律（都在真实事故里出现过）

1. **自动链只放可自动的。** 需要人播放、人授权、人点确认的通道，只做兜底按钮，不进自动降级链——自动跑等于假装在下载。
2. **「能抓到」必须自触发验证。** 「调试器挂上了」「接口返回 200」都不是证据。真判据是：自己造一次请求，然后断言抓到 ≥1 条。否则「挂上了」会长期冒充「看得见」。
3. **可行动的错误 > 精确的错误。** 把 `Extension has not been invoked for the current page` 原样丢给用户等于没报错；正确做法是翻译成「去 chrome://extensions → 详情 → 网站访问权限，改成在所有网站上」。同一句原文往往只有两个真实原因，把两个都写上。
4. **加密正确性用逐字节比对，不用体积。** HLS 的 IV 推导（不带 IV 时用分片序号大端）写错，下下来的文件**体积完全正确、内容全是乱码**。体积、时长、码率都能骗人，逐字节不能。
5. **大文件内存预算属于产品可用性，不是性能优化。** 「分块 + `new Uint8Array(total)` + Blob 复制」峰值 ≈ 2× 文件体积；200 MB 的单文件在低配机器上直接卡死。能用 Blob 组装就别拼连续 buffer；只有需要喂给 wasm 解码器的那一段才付这份内存。

## 四、三条与上下文强相关的实现约束（实测，跨产品通用）

1. **CDP 不能跑在 service worker。** 同一段 `chrome.debugger.attach` + `Network.enable` + 监听：SW 里 8 秒收到 **0 条** `responseReceived`，扩展页面里 8 秒收到 **32 条**。MV3 的 SW 会被挂起，调试会话跟着断。
2. **tabCapture 只对当前活动标签页生效。** 面板是扩展页、目标 tab 在后台时 `getMediaStreamId` 直接拒绝；必须先 `tabs.update({active:true})` + `windows.update({focused:true})`。同一个报错还有第二个来源：站点访问权限被收窄成「点击时」——那时 content script 也不自动注入（**两个症状同一根因**）。
3. **站点 Service Worker 直接返回的请求对 `webRequest` / DNR 不可见**（Chromium 2018 年起的限制）。`browsingData.remove({origins}, {serviceWorkers, cacheStorage})` 抹掉后让请求重走网络，是可行解法之一。

## 五、证据分级与功能基线

每条通道单独锚一个 `baseline/*` tag，并如实标注证据级别：

| 级别 | 含义 |
|---|---|
| A | 有可复跑的测试，或实测产物经独立工具校验（ffprobe / 逐字节比对） |
| B | 代码完整、错误路径可复现，但关键成功路径未跑通（如环境权限受限） |
| C | 只有 commit message 佐证 |

**纪律**：代码写完 ≠ 验证通过。一个通道「本机站点权限被收窄所以录不了」就是 B，不许写成 A。模板见 `templates/BASELINE_TAGS.tsv`。

## 六、不做什么

- **不做 DRM 破解**：Widevine / PlayReady / CENC / SAMPLE-AES 的 key 获取与解密不在 Prism 与任何交付项目的范围内。取流层梯到「加密层」为止：能证明「这是加密流」就够，不提供解密路径。
- **不把私有参数写进本仓**：签名盐、CDN 口令、设备指纹、账号 Cookie 一律留在产品主库或私有目录。
- **不把「抓到了字节」当成「可以分发」**：版权与站点条款是独立于技术的一层。

## 何时调用本文件

| 任务 | 本文件的作用 |
|---|---|
| 审计一个「下载 / 取流 / 嗅探」类产品 | 用层梯判断它到底覆盖了哪几层、哪些是假覆盖 |
| 判断某条「下不了」的结论是否成立 | 查第一节目录：上下文 / API / 失败返回三要素齐不齐 |
| 给取流能力排优先级 | 按层梯的「代价」列，先补便宜且能自动的层 |
| 设计验证方案 | 用第三节五条纪律检查「是不是在自证」 |
