# 视觉闭环：观察 → 定位 → 执行 → 验证

2026年11月3日 · macOS 实测。

## 一、盲操作 vs 闭环

| | 盲操作 | 闭环 |
|---|---|---|
| 形态 | 点一下、打个字、结束 | 每步都能看到结果并纠错 |
| 出错时 | 不知道错了，继续往下错 | 当步就能发现并重试 |
| 依赖 | 坐标算得准 | 只依赖「能不能认出目标」 |

实测的六步（可复现）：

| 步 | 动作 | 输出 |
|---|---|---|
| 1 | 快照 | `shotHash b3d603…` / 44 个结构节点 |
| 2 | 按角色定位 | `AXTextArea @ (536,432)` |
| 3 | 点击 | 命中 `text area 1 of scroll area 1 of window 未命名14` ✅ |
| 4 | 输入 | 18 字符 |
| 5 | 再快照 | `shotHash 09123a…` **变了** ✅ |
| 6 | 读回确认 | 内容正确 ✅ |

## 二、三个设计要点

### 2.1 坐标是**结果**，不是**输入**

错误形态：让模型看图 → 估一个坐标 → 拿去点。
正确形态：模型说「点保存」→ 由「找元素」这一步算出坐标。

**把坐标当输入，等于让模型去猜像素。** 模型对像素的估计本就不可靠，
再加上 Retina 缩放，误差会被放大一倍。

### 2.2 定位优先用**结构**，不用**像素**

| 方式 | 得到什么 | 可靠性 |
|---|---|---|
| 辅助功能树 | 角色 + 名字 + 位置（逻辑坐标） | 高，可断言 |
| 读屏 OCR | 文字 + 像素框 | 中，需换算坐标 |

所以：**先查结构树，找不到才用 OCR 兜底**。OCR 的坐标必须做物理→逻辑换算。

### 2.3 验证要看「变没变」，不能看「没报错」

快照要同时取两样：

| 取什么 | 能发现 | 会漏掉 |
|---|---|---|
| 截图指纹 | 画面整体变化 | — |
| 结构摘要 | 控件增减、名字变化 | 结构没变但内容变了（输入框里多了字） |

反过来：

| 取什么 | 会漏掉 | 会被干扰 |
|---|---|---|
| 只取截图 | — | 光标闪烁、时钟跳秒、通知弹窗 |
| 只取结构 | 「内容变了但结构没变」 | — |

**两样都要**，缺一个就有整类失败看不见。

## 三、闭环该由谁编排

**工具只提供原子能力，循环由调用方编排。**

```
snapshot -> find(目标) -> click -> snapshot -> 比对
   ^                                        |
   +------------ 不一致就重来 <--------------+
```

把「思考」塞进工具里是错的：

- 工具不知道自己想干什么
- 工具也不该替调用方决定「重试几次 / 换个目标」
- 一旦工具里塞了决策逻辑，就没法复用到别的任务

**工具负责「看得准、点得中、验得出」，调用方负责「想清楚要做什么」。**

## 四、检查清单

- [ ] 坐标是「找出来的」还是「猜出来的」？能不能改成按语义定位？
- [ ] 定位是否优先用结构树、OCR 只做兜底？
- [ ] 每个写操作后是否有一次快照对比？
- [ ] 快照是否同时包含「画面指纹」和「结构摘要」？
- [ ] 闭环的循环逻辑在调用方，而不是埋在工具里？
- [ ] 失败时是否能定位到「哪一步没生效」，而不是只说「没成功」？
